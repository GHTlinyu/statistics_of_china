# 01 需求规格：登录 / 注册验证码

- 功能 slug：`captcha`
- 状态：已确认并实现
- 日期：2026-10-30

## 背景与目标

`POST /auth/login` 与 `POST /auth/register` 目前没有任何预验证，攻击者可以直接对用户名/密码进行持续尝试。需要在凭据校验之前增加一次性图片验证码，提高自动化暴力破解的成本。

## 需求条目

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R1 | 验证码接口 | `GET /auth/captcha`，公开访问，返回 `captcha_id`、PNG data URL 与有效期。 |
| R2 | 登录校验 | `POST /auth/login` 必须携带 `captcha_id` + `captcha_code`，先校验验证码，再校验用户名密码。 |
| R3 | 注册校验 | `POST /auth/register` 同样必须携带验证码，防止批量注册。 |
| R4 | 图片形式 | 4 位字符 PNG 图片（160×60，带干扰），字符集去掉易混淆的 `0/O/1/I`。 |
| R5 | 有效期 | 默认 5 分钟，可通过 `Settings` 配置覆盖。 |
| R6 | 一次性 | 每次校验无论成功失败都销毁记录，禁止重放。 |
| R7 | 安全存储 | 数据库只保存验证码的 HMAC-SHA256 摘要，不保存明文。 |
| R8 | 错误语义 | 验证码缺失/错误/过期统一 400，文案「验证码错误或已过期」，不泄露具体原因。 |
| R9 | 存储 | 使用 PostgreSQL `captcha` 表，签发时顺带清理过期记录。 |
| R10 | 本期范围 | 不增加失败限流/锁定、不接入第三方人机验证、不做邮箱/短信验证码。 |

## 非目标

- 登录失败限流 / 账户锁定（后续需要）
- 第三方人机验证（Cloudflare Turnstile / reCAPTCHA）
- 邮箱 / 短信验证码
- 验证码管理页面

## 验收标准

1. `GET /auth/captcha` 无需 token，返回的 `image` 是可解析的 PNG data URL，响应中不含明文验证码。
2. 登录 / 注册不带验证码字段时返回 422。
3. 错误、过期、重复使用的验证码均返回 400，且不签发 token / 不创建用户。
4. 正确验证码 + 正确凭据可以登录；正确验证码 + 新用户名可以注册。
5. 同一验证码成功使用后再次提交返回 400。
6. 数据库中只能查到 `code_hash`、`expires_at`，查不到明文。
7. 前端登录页可以显示、刷新验证码，登录失败后自动刷新。
8. 原有密码错误 401、用户名重复 409 的语义保持不变。
