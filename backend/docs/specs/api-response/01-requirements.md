# 01 需求规格：通用响应结构

- 功能 slug：`api-response`
- 状态：已确认
- 日期：2026-10-26

## 背景与目标

当前各接口直接返回裸数据或 FastAPI 默认错误结构（`{"detail": "..."}`），前端需要为每个接口适配不同格式。需要统一的响应结构，并改造现有接口，使后续开发接口默认使用该结构。

## 需求条目

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R1 | 统一响应结构 | 形如 `{"code": 200, "message": "success", "data": ...}`；业务成功 `code` 恒为 200，`message` 默认 `"success"`。 |
| R2 | 改造现有接口 | `/auth/register`、`/auth/login`、`/auth/me`、`/user/{id}`、`/health` 全部使用统一结构返回。 |
| R3 | 业务异常统一 | 业务代码抛出的 `HTTPException`（401/404/409 等）返回统一结构：`code` 为对应 HTTP 状态码，`message` 为错误描述，`data` 为 null。框架层异常（未匹配路径 404、405、参数校验 422）保持 FastAPI 默认格式。 |
| R4 | 后续接口默认使用 | 除特殊处理（需在接口文档中注明理由）外，新接口一律使用统一结构。 |
