# 01 需求规格：长期记忆

- 功能 slug：`memory`
- 状态：已确认并实现
- 日期：2026-10-29

## 背景与目标

聊天主链路已具备「知识库检索 → 大模型生成」，但 `chatService` 固定传入空 `memories`，跨会话的用户偏好与回答指导无法保留。本期把已有的记忆模型与 `finder` / `extractor` / `updater` 接入聊天流程，形成「读记忆 → 回答 → 写记忆」闭环。

## 需求条目

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| M1 | 记忆类型 | 仅支持 `user`（长期偏好、习惯、关注方向）与 `feedback`（对回答方式的长期指导）。 |
| M2 | 容量上限 | 每个用户最多 10 条长期记忆。 |
| M3 | 读路径 | 每轮提问前读取用户记忆目录（最多 10 条），结合最近 2 条用户消息与本轮问题（约 3 轮上下文）由 finder 选出相关记忆；选中 ID 回表校验后注入 prompt。 |
| M4 | 写路径 | 回答成功落库后，取最近 10 轮对话（最多 20 条消息）由 extractor 生成 `CREATE` / `UPDATE` 操作并落库。 |
| M5 | 容量淘汰 | 新增时已满 10 条：同类型记忆存在时由 updater 决定 `MERGE` 或 `REPLACE`（替换最旧同类型记忆）；无同类型记忆时直接替换全局最旧一条。 |
| M6 | 数据隔离 | 所有查询与写入都限定当前 `user_id`；模型返回的 `memory_id` 必须回表校验归属，非法 ID 忽略。 |
| M7 | 失败降级 | finder / extractor / updater 任一失败只记日志：读路径按「无记忆」继续，写路径跳过本轮写入，不得影响聊天主链路。 |
| M8 | 不阻塞流式 | 写路径在 `done` 事件后以后台任务执行（线程池），不延迟或阻塞 SSE。 |
| M9 | 本期范围 | 只接入聊天链路；不提供记忆管理 API / 前端页面，不做记忆向量检索与跨用户共享。 |

## 非目标

- 记忆列表、编辑、删除接口
- 记忆的向量化检索（当前为目录 + LLM 筛选）
- 多用户共享记忆、组织级记忆
- 记忆冲突的人工仲裁界面

## 验收标准

1. 用户无长期记忆时，聊天行为与接入前一致，不额外调用 finder。
2. 用户存在记忆且与当前问题相关时，`generate_node` 的 prompt 中出现对应记忆内容。
3. 回答完整落库后，后台自动执行提取；新记忆的 `memory_type`、`title`、`content` 正确，`source_conversation_id` 为本轮会话。
4. 记忆达到 10 条后继续产生新记忆时，走 updater 合并或替换，数量不超过 10。
5. finder / extractor 抛异常时，聊天仍能正常返回 `start` / `token` / `done`。
6. 客户端中途断开（未走到 `done`）时只保存部分回答，不触发记忆提取。
7. 越权 `memory_id` 不会出现在任何读写结果中。
