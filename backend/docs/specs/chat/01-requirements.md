# 01 需求规格：聊天（SSE 流式问答）

- 功能 slug：`chat`
- 状态：已确认并实现
- 日期：2026-10-29

## 背景与目标

用户需要在会话里提问，由 Agent 工作流完成「知识库检索 → 大模型生成」，并把回答以流式方式返回。前端需要一个通用、可扩展的事件结构，后续能平滑加入工具调用、引用来源等事件。

## 需求条目

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R1 | 聊天接口 | `POST /conversation/{conversation_id}/chat`，请求体 `{content}`，返回 SSE 流。 |
| R2 | 通用事件结构 | 每个事件统一为 `{"type": ..., "data": {...}}`，`type` 取 `start` / `token` / `done` / `error`。 |
| R3 | 会话归属 | 只能对自己的会话发起聊天，越权或已删除返回 404；404 必须在流开始前返回。 |
| R4 | 短期上下文 | 取该会话最近 20 条消息（不含本轮问题）转成 `HumanMessage` / `AIMessage` 作为 history。 |
| R5 | 消息落库 | 流开始前保存本轮 user 消息；流结束后保存 assistant 消息（内容为完整回答）。 |
| R6 | 停止生成 | 客户端断开或用户停止时，保留并落库已经生成的部分回答。 |
| R7 | 会话标题 | 会话标题为空时，用首条用户消息的前 20 个字自动填充。 |
| R8 | 活跃时间 | 每轮对话刷新 `conversation.updated_at`，会话列表按最近活跃排序。 |
| R9 | 消息 CRUD | 新增消息 `POST /conversation/{id}/messages`、删除消息 `DELETE /conversation/{id}/messages/{message_id}`；查询沿用现有分页接口。 |
| R10 | 参数校验 | `content` 长度 1~4000；消息 `role` 仅允许 `user` / `assistant` / `system`。 |
| R11 | 错误处理 | 生成失败时返回 `error` 事件（固定错误码与文案），详细异常只进日志。 |
| R12 | 本期范围 | 只做聊天主链路；长期记忆（finder / extractor）不接入，`memories` 固定为空。 |

## 非目标

- 长期记忆读写（后续版本）
- 追问的 query 改写
- 工具调用事件、引用来源、token 用量统计
- 多会话并发限制、消息重试
- 前端聊天页面（另行开发）

## 验收标准

1. `POST /conversation/{id}/chat` 返回 `text/event-stream`，依次出现 `start`、若干 `token`、`done`。
2. `done` 事件带 `conversation_id` 与 `message_id`，库里能查到对应的 user / assistant 消息。
3. 会话不存在或越权时返回 404（普通 JSON，不是半截 SSE 流）。
4. 生成中途关闭连接，已生成的部分回答仍会落库。
5. 首轮对话后会话标题自动填充，且会话列表排序刷新。
6. 消息增删接口可用，越权访问返回 404，非法参数返回 422。
